## What This Project Is

**BipPoyAI** (branded "Qwythos AI") is a **local-only AI desktop application** for Windows.
It lets you run a GGUF model entirely offline using:

```
User (Claude CLI or GUI chat)
        │
        ▼
  LiteLLM Proxy  :4000
  ← spoofs the Anthropic API so `claude` CLI works offline without any internet
        │
        ▼
  Ollama  :11434
  ← hosts the GGUF model (currently Qwythos-9B-Claude-Mythos-5-1M-MTP-Q4_K_M)
        │
        ▼
  Qwythos-9B.gguf  (≈5.8 GB, local file)
```

**Key architectural fact:** LiteLLM is mandatory — it is not optional middleware.
It exists specifically to spoof `api.anthropic.com` so that the `claude` CLI (Claude Code)
connects to it thinking it's talking to Anthropic, but actually routes to Ollama locally.
`setup.py` sets `ANTHROPIC_BASE_URL=http://localhost:4000` + `ANTHROPIC_API_KEY` env vars to make this transparent.

There are **two ways to use the stack:**
1. **GUI** (`main.py`) — chat interface, sends requests to LiteLLM directly
2. **Claude CLI** — `claude --model <tag>`, routed through LiteLLM → Ollama

## Design System

### Visual Theme: Pip-Boy
Amber readout on weathered dark green. Like a Fallout wrist computer.

- **Monospace everywhere** — font stack: Cascadia Mono → JetBrains Mono → Consolas → DejaVu Sans Mono
- **Amber is text, green is background** — never reversed
- `COLORS` dict in `styles.py` is the single source of truth for all palette values
- QSS stylesheets live entirely in `styles.py` — no inline QSS strings in `main.py` except one-off bubble overrides
- Custom painted widgets (texture, glow, LEDs, knobs) live in `widgets.py` — QSS cannot express these

### Widget Conventions
- `CrackedBackdrop` + `ScanlineOverlay` — always full-window, always `WA_TransparentForMouseEvents`, resized in `resizeEvent`
- `LEDDot.set_state()` — states: "green", "amber", "red", "off"
- `HardwareStrip.set_lamps(pwr, io, gpu)` + `set_plate(text)` — called from `_sync_hw_strip()` in MainWindow
- `BarMeter.set_level(0.0-1.0)` — driven by `tokens_per_sec / 30.0`

## Key Patterns

### Config round-trip (always use this)
```python
from pathlib import Path
from configs import load_full, write_all, ModelConfig

cfg = load_full(Path(working_dir))          # reads Modelfile + config.yaml
cfg2 = cfg.with_updates(context_size=65536) # immutable update
write_all(cfg2, Path(working_dir))          # writes both files
```
Never hand-roll Modelfile/config.yaml strings in the GUI. That was the V0.1 bug we fixed in V0.2.

### Backend URL access (V0.3 will fix the constants)
Currently `backend.py` has module-level `OLLAMA_BASE_URL` and `LITELLM_BASE_URL` constants.
V0.3 moves these onto the `OllamaBackend` instance with an `update_urls()` method.

### Streaming signals (ChatWorker)
```
token_received(str)       → append to bubble, scroll
generation_complete(str)  → finalize, auto-save history
error_occurred(str)       → render error bubble
stats_update(dict)        → drive BarMeter + HardwareStrip plate
```

### Status signal flow
```
backend.check_status() (every 5s)
  → ollama_status_changed("live"|"offline")            → LEDDot + _sync_hw_strip + _update_banner
  → litellm_status_changed("live"|"offline")           → LEDDot + _sync_hw_strip + _update_banner
  → model_status_changed("ready"|"not_found"|"unknown") → LEDDot + _sync_hw_strip + _update_banner
  → model_list_updated(list[str])                      → (V0.3) model switcher dropdown
```

## How to Run

```powershell
# Install deps (once)
pip install -r requirements.txt

# Launch GUI
python main.py
# or double-click:
launch.bat

# Full setup (first time or new model)
setup.bat
# or
python setup.py

# Terminal config TUI (hardware tuning without the GUI)
python config.py
```

**Prerequisites:**
- Python 3.11+
- Ollama installed and running (`ollama serve`) — https://ollama.com
- `Qwythos-9B-Claude-Mythos-5-1M-MTP-Q4_K_M.gguf` in this folder (≈5.8 GB)
- `litellm` available in PATH (satisfied by `pip install -r requirements.txt`)

## Gotchas & Known Issues

| Issue | Notes |
|---|---|
| Backend URLs are hardcoded constants | V0.3 fix. `OLLAMA_BASE_URL` / `LITELLM_BASE_URL` in `backend.py` are module constants. Changing them in Settings requires app restart until V0.3 lands. |
| Modelfile missing some hardware params | Current on-disk `Modelfile` only has `num_ctx` and `temperature`. Run Settings → Save & Rebuild to write full `num_gpu`, `num_thread`, `num_batch` params. |
| `model_list_updated` signal unused | Signal exists in `backend.py` and is emitted every poll cycle, but nothing connects to it yet. V0.3 model switcher will consume it. |
| `scratchpad.md` is stale | Config integration items it tracked are now done in V0.2. Safe to delete. |
| `.routing_mode` not read by GUI | Written by `setup.py`/`config.py` TUI. GUI reads engine mode from `config.yaml` via `configs.load_full()` instead. Keep these in sync manually for now. |
| No recovery if LiteLLM crashes mid-generation | Status banner re-appears and blocks new sends, but in-flight generation hangs. User must click Stop manually. |
