### The bug that was closed

Heretic's GGUF chat template contained seven `raise_exception('No user query found in messages.')` guards. Any `tool_result` turn where the assistant message had no accompanying user text hit one of them, producing an HTTP 500 from LiteLLM. This surfaced on large-file analysis because long tool results made the Claude Code turn pattern reproducible.

Symptoms the user saw across attempts: 500 error, silent empty response, or the client hanging.

Fix: all seven guards rewritten to equal-length Jinja comments (`{# ... #}`) so the tensor/metadata layout is untouched. **Original weights were never modified — only patched copies.**

Patcher lives at `tools/gguf_guards.py` and is committed. Active weights:
`E:\Models\Qwen3.5-9B-Heretic\Qwen3.5-9B-Heretic-patched2.gguf`

The regression probe that guards this is committed at `tests/test_toolresult_turn.py`.
Run it against a live LiteLLM before and after any change to the Heretic GGUF,
template handling, or LiteLLM version:

```

```

Expect `PASSED - no template exception`. If this test starts failing with
`No user query found in messages.`, a guard has come back — re-run the patcher

## Open bugs (discovered by a *deliberate* failure, not left broken)

A 400 (`Invalid model name passed in`) was hit while testing the 2B model. That 400 was **correct behaviour** — the wildcard was removed on purpose so unknown models fail loudly instead of silently serving Heretic. But it surfaced three separate defects. All three are still unfixed.

### 1. `derive_model_tag` lowercasing — highest priority

The GUI dropdown is populated from Ollama, which returns names with capitals, e.g. `Qwen3.5-2B-Uncensored-HauhauCS-Aggressive-BF16`. `derive_model_tag()` lowercases it to `qwen3.5-2b-uncensored-...`. The tag written to `config.yaml` therefore can never match what Claude Code requests from that same dropdown. **Any model with capitals in its name breaks on save.**

Fix direction: when a registered Ollama tag already exists for the selected GGUF, preserve that tag rather than deriving a lowercased one.

### 2. `num_ctx` is unguarded

`coherence_issues()` validates the model tag but not sizing. The GUI combo can write a VRAM-hostile `num_ctx` — observed drifting to 65536, which pushed roughly 24% of layers onto CPU. On the RTX 2070 SUPER, 32768 gives ~9.8 tok/s at 100% GPU.

Fix direction: clamp or validate `context_size` in the coherence check.

### 3. Saving config does not restart LiteLLM

Editing `config.yaml` does not reload LiteLLM. Observed directly: `/v1/models` still advertised the old model while `config.yaml` had already been rewritten. Every config change needs a manual restart, which is the likely root of the stale-model confusion during model switching.

Fix direction: trigger a LiteLLM reload on save, or surface an explicit "restart required" state.

## Gotchas that will bite again

- **Ollama caches resident models.** After `ollama create`, force-unload/restart Ollama or it serves the *old* weights and you will debug a fix that already works.
- **`config.yaml` changes need a LiteLLM restart** to take effect (see open bug 3).
- **`CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS=1`** is set, so no `?beta=true` path — matching LiteLLM's behaviour matters.
- **Never restore `model_name: "*"`.** The wildcard silently routed every model name to Heretic and made model-switching tests produce false positives.
- The raw-byte guard scanner in `tools/gguf_guards.py` could report false negatives for compressed chat-template storage.

## Environment notes

- Claude Code routes via LiteLLM on localhost:4000 using a **local placeholder** auth token (not a real credential; defined in the launcher env in `main.py`). Do not commit real credentials.

- `claude` is launched **without** `--model`; `ANTHROPIC_MODEL` is used instead. Passing `--model` causes an `unrecognized_model` hang. Any remaining warning about that is cosmetic.
